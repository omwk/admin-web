- 依赖：FE-1（`v0.FE-1`）、后端 `F1`/`F2`/`F3`（已合并）
- 预计：**7 人日**
- 分支：`feat/fe-1.5-system`
- 完成标志：管理员能在界面上邀请新同事、建角色并授权、调整菜单；全程不碰数据库

## 1. 为什么先做这三页

现在唯一的管理入口是「用户只读列表」。要加一个同事，必须改数据库：

```
建用户 → SQL
分配角色 → SQL
调整菜单 → SQL
```

这三页做完，框架才算「运营能用」。

## 2. 接口（后端已就绪）

## 3. 页面

### 3.1 用户管理

- 列表：用户名、昵称、部门、角色、状态、创建时间；支持 keyword/status 筛选
- 新建：两种入口
  - **邀请**（推荐）：选部门、选角色、有效期 → 生成链接，可复制
  - 直接建号：填用户名与初始密码（标记强制改密）
- 编辑：昵称/邮箱/部门/状态
- 行操作：分配角色、重置密码、生成重置链接、禁用、删除

### 3.2 角色管理

- 列表 + 新建/编辑/删除
- 授权抽屉，三个页签：
  - **菜单**：树形复选（父子联动）
  - **权限**：按 `module:resource` 分组折叠，支持全选模块、搜索
  - **数据范围**：部门树 + 范围类型（全部/本部门/本部门及下级/仅本人/自定义）

### 3.3 菜单管理

- 树形表格，支持新增子项、编辑、删除
- 字段：名称、类型（目录/菜单/按钮）、路径、组件、图标、排序、可见、权限码

### 3.4 部门

- 只读树，供用户与角色选择（不做增删改，留 F4）

## 4. 关键实现要求

### 4.1 权限码展示

后端返回按 module 分组。前端渲染为**折叠面板**：

```
system    (12)  ← 默认折叠
catalog   (8)
trade     (15)
...
```

每个面板内是「资源 + 动作」的复选网格。支持按码搜索。

### 4.2 菜单树与权限码的联动

菜单节点本身带 `permission_code`。勾选菜单**不等于**授予该菜单下所有接口权限——两者独立。界面上要提示这一点，避免管理员以为勾了菜单就有权限。

### 4.3 删除的保护

- 删除角色时若仍被用户引用 → 后端返回 409，前端提示「先解除用户关联」
- 删除菜单时若仍有子节点 → 提示先删子节点

### 4.4 邀请链接的展示

生成后弹窗显示链接 + 复制按钮，并提示：

```
链接有效期 7 天，只能使用 1 次。
对方的密码由本人设置，你无法看到。
```

## 5. 验收

| # | 项 | 断言 |
| --- | --- | --- |
| 1 | 邀请 | 生成邀请 → 打开链接 → 设密码 → 登录成功，落到预置部门与角色 |
| 2 | 邀请管理 | 列表显示状态；撤销后链接失效 |
| 3 | 用户编辑 | 改昵称/部门后列表即时更新 |
| 4 | 分配角色 | 勾选两个角色保存后，重新打开仍勾选 |
| 5 | 重置链接 | 生成链接可复制；用后再次生成新链接，旧链接失效 |
| 6 | 角色授权 | 勾选菜单/权限后保存，重新打开回显一致 |
| 7 | 权限分组 | 103 个权限码按 module 分组显示，可搜索、可整组勾选 |
| 8 | 数据范围 | 五种范围类型可切换；自定义部门树可多选 |
| 9 | 菜单 CRUD | 新增子菜单后侧边栏出现（重新登录后） |
| 10 | 删除保护 | 删除被引用的角色返回 409 并提示 |
| 11 | 无权限 | 无 `system:user:create` 的账号看不到新建按钮，直接调接口仍 403 |
| 12 | 构建 | lint / typecheck / unit / build 全绿 |
