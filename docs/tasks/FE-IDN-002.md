## 1. 接口

### 租户设置（租户超管 / 平台管理员）

```
GET /admin/settings/tenant      → 三项含 schema 与默认值
PUT /admin/settings/tenant      → 批量保存
```

| key | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `allow_self_registration` | boolean | false | 允许邮箱验证后自助注册 |
| `default_role_code` | string | `""` | 非首用户的默认角色，空值 = 无角色 |
| `registration_hourly_limit` | number | 10 | 每租户每小时注册请求上限（1–10000） |

三项都是 `hot_reload: true`。

### 注册（匿名）

```
POST /auth/register
{ "tenant": "acme", "account": "alice", "password": "...", "email": "a@b.com" }
→ 201 { accepted: true }                     首次
→ 202 { accepted: true }                     重复账号/邮箱（形状相同）
→ 403 / 20111  开关关闭
→ 429 / 10005  超过每小时上限
→ 401 / 20101  租户不存在（与密码错误同一文案）
dev/test 环境额外返回 dev_verify_url
```

### 验证（匿名）

```
POST /auth/register/verify { "token": "..." }  → 204
无效/过期/已用 → 400「邀请或链接无效」
```

## 2. 页面

### 2.1 租户设置页（`/system/settings` 的新页签「注册」）

或系统设置页里新增一组 `tenant`：

| 项 | 控件 | 说明 |
| --- | --- | --- |
| 允许自助注册 | 开关 | 打开时下方两项才可编辑 |
| 默认角色 | 角色下拉（来自 `/admin/roles`） | 含「无角色（最小权限）」选项 |
| 每小时上限 | 数字输入 | 1–10000 |

**必须显示的风险提示**（放在开关下方）：

```
开启后，任何知道本企业代码的人都可以注册账号。
新用户需要完成邮箱验证才能登录。
非首位用户将获得「默认角色」的权限——请确认它不是高权限角色。
```

保存后提示「已生效」。

### 2.2 注册页（公开，无登录态）

路由：`/auth/register?tenant=acme`

| 字段     | 校验                                                     |
| -------- | -------------------------------------------------------- |
| 企业代码 | 必填；从 URL 带入时只读                                  |
| 账号     | 必填，≤256                                               |
| 邮箱     | 必填，格式校验                                           |
| 密码     | 必填，8 位以上，含字母与数字（前端先校验，后端最终裁定） |
| 确认密码 | 与密码一致                                               |

提交后统一提示（不区分首次/重复）：

```
如果信息有效，我们已向你的邮箱发送验证邮件，请查收。
```

**不要**显示「该账号已存在」——后端的 202 语义就是不泄露账号是否已注册。

错误处理：

| 状态 | 展示                                               |
| ---- | -------------------------------------------------- |
| 403  | 「该企业未开放自助注册」                           |
| 429  | 「注册过于频繁，请稍后再试」                       |
| 401  | 「企业代码不存在」（与密码错误同文案时使用同一句） |

### 2.3 验证页（公开）

路由：`/auth/register/verify?token=...`

- 加载即调用 `POST /auth/register/verify`
- 成功：显示「邮箱已验证，现在可以登录了」+ 登录按钮
- 失败：显示「链接无效或已过期」+「重新注册」链接

### 2.4 登录页入口

登录页底部加一行：

```
还没有账号？联系管理员邀请，或在此注册
```

「在此注册」仅在**当前填写的企业代码已开放注册**时可用——但为避免枚举，
不要调用任何「查询是否开放」的接口。做法：直接跳转注册页，由提交结果决定。

## 3. 验收

| #   | 项         | 断言                                       |
| --- | ---------- | ------------------------------------------ |
| 1   | 设置读取   | 三项显示后端值与默认值                     |
| 2   | 关闭状态   | 开关关闭时默认角色与上限禁用               |
| 3   | 保存       | 开启后保存，刷新仍为开启                   |
| 4   | 风险提示   | 开启示显示三条风险说明                     |
| 5   | 注册成功   | 提交后统一提示，不显示「已存在」           |
| 6   | 重复注册   | 同账号再提交，提示与首次相同               |
| 7   | 关闭时注册 | 显示「该企业未开放自助注册」               |
| 8   | 验证页     | 有效 token → 成功提示；无效 → 失败提示     |
| 9   | 验证后登录 | 验证完成可正常登录；未验证登录被拒并提示   |
| 10  | 首用户     | 空租户首个注册者验证后为超管（与后端一致） |
| 11  | 密码校验   | 8 位以下/纯字母被前端拦截                  |
| 12  | 构建       | lint / typecheck / unit / build 全绿       |

## 4. 不做

- 注册页图形验证码
- 手机号注册
- 邀请与注册的统一入口页
- 企业代码的「是否开放」探测接口（会泄露信息）
