## 1. 背景

审计页当前把 before/after 原样摊开。读操作的两份数据相同，
看起来像"改了什么但看不出改了什么"。

## 2. 改动

### 2.1 差异展示

| 情况                   | 展示                              |
| ---------------------- | --------------------------------- |
| before 与 after 都为空 | 显示「—」                         |
| 只有 after（新建）     | 显示「新建」+ 字段表              |
| 只有 before（删除）    | 显示「删除」+ 字段表              |
| 两者都有且相同         | 显示「无变化」                    |
| 两者不同               | 逐字段对比：旧值删除线 / 新值高亮 |

### 2.2 列与筛选

| 项 | 改动 |
| --- | --- |
| 「操作」列 | action 点号形式显示为中文化名称（映射表见后端 `audit-events.md`） |
| 「目标租户」列 | 跨租户操作显示 target_tenant（来自 after 元数据） |
| 筛选 | 增加「结果」「来源 IP 是否为空」？——先只保留现有筛选 |
| 详情 | 读操作显示「访问范围：12 个租户」而非字段对比 |

### 2.3 来源信息

IP / User-Agent 为空时显示「—」，不要显示空白单元格。

## 2.4 人员与资源的可读名称（核心）

现状：审计只显示「用户 #1」「租户 #2」。用户列表本身也不展示 id，**无法反查**。

后端 BE-IDN-009 新增 ctor_name / ctor_tenant_name / esource_label 后，前端改为：

| 列     | 显示                                         | 为空时      |
| ------ | -------------------------------------------- | ----------- |
| 操作者 | dmin（default）                             | 用户 #1     |
| 对象   | 租户 acme / 用户 sales01 / 字典 order_status | #2          |
| 操作   | 中文名 + 原始 action 悬浮提示                | 原始 action |
| 结果   | 成功 / 失败（失败悬浮显示 error_message）    | —           |

## 2.5 筛选与搜索

| 控件 | 说明 |
| --- | --- |
| 关键字 | 搜索操作者名、对象名、action（调用 keyword） |
| 模块 | 下拉：身份 / 租户 / 字典 / 通知 / 同步 / 计费 …（映射为 ction_prefix） |
| 结果 | 成功 / 失败 |
| 时间范围 | 保留 |

## 2.6 用户列表补 ID 列

/system/users 表格增加 ID 列（等宽、可复制）。

理由：审计里仍有 #id 兜底显示，需要能反查；同时客服排障经常需要用户 id。

## 2.7 失败记录

esult=failure 的行：

- 结果列显示「失败」+ 红色标记
- 展开详情显示 error_code 与 error_message
- 失败原因的敏感值已由后端脱敏，前端原样展示
