## 1. 为什么订单页是下一个

- 它是**唯一每天都要用的业务页**（客服查单、对账查单）
- 它包含**本系统唯一的高敏数据路径**（收货人 PII + 重认证），这条链路验证完，
  后续所有敏感数据场景（客户手机号、询价单）都能复用

## 2. 接口（已就绪）

| 接口                             | 用途     | 备注                     |
| -------------------------------- | -------- | ------------------------ |
| `GET /admin/orders`              | 列表     | 分页、状态/时间/店铺筛选 |
| `GET /admin/orders/{id}`         | 详情     | 商品行、金额、状态       |
| `GET /admin/orders/{id}/address` | 收货信息 | **需 5 分钟内重认证**    |
| `GET /admin/orders/stats`        | 统计聚合 | 卡片区                   |
| `POST /admin/orders/export`      | 触发导出 | 需 `Idempotency-Key`     |
| `GET /admin/orders/exports/{id}` | 导出状态 |                          |

## 3. 页面

### 3.1 列表

- 列：订单号、店铺、买家、金额、状态、下单时间、最后同步
- 筛选：状态（多选）、店铺、时间范围、关键词（订单号/买家）
- 金额用 FE-2 的 `money.ts`，禁止浮点
- 翻页沿用 FE-1 的分页组件

### 3.2 详情

- 概览：订单号、状态、金额构成（商品/运费/优惠/实付）、时间线
- 商品行：标题、SKU、数量、单价、小计
- 收货信息区：**默认脱敏**（`张*` / `138****8000` / `上海市***`），
  点击「查看完整信息」→ 触发重认证 → 成功后才请求 `/address`

### 3.3 重认证流程（重点）

```
点「查看」→ 弹窗输入密码 → POST /auth/reauth
  → 成功：拿到 reauth 凭证（5 分钟有效）
  → 失败 401/20101：提示密码错误
  → 之后请求 /address 带上该凭证
  → 凭证过期（5 分钟）→ 再次点击时重新要求输入
```

**禁止**把 PII 缓存在前端 store 或 localStorage；离开页面即丢弃。

## 4. 关键要求

### 4.1 PII 三条红线

1. 列表**不得**出现收货人任何字段（后端也不返回）
2. 详情默认脱敏，完整信息只在重认证后、在内存中
3. 复制/导出按钮对 PII 字段禁用；控制台不得打印

### 4.2 空态与错误

- 无订单：空态引导「同步店铺后可见」
- 重认证失败：提示「密码错误」，不消耗次数提示
- 401：走既有刷新逻辑，不自动重试 `/address`

### 4.3 导出

- 触发后轮询状态，完成后给下载链接
- 导出请求携带当前筛选条件
- 失败显示后端原因，不吞错

## 5. 验收

| # | 项 | 断言 |
| --- | --- | --- |
| 1 | 列表渲染 | 真实订单数据 ≥5 行，金额/时间格式正确 |
| 2 | 筛选 | 状态与店铺筛选后 total 变化正确 |
| 3 | 详情 | 商品行金额合计等于订单实付 |
| 4 | PII 默认脱敏 | 未重认证时页面无完整手机号/地址（DOM 与网络请求双重检查） |
| 5 | 重认证 | 输错密码提示错误；正确后显示完整信息 |
| 6 | 5 分钟过期 | 凭证过期后再点查看，重新要求输入 |
| 7 | 不落盘 | 重认证后 localStorage/sessionStorage 无 PII |
| 8 | 统计卡片 | 与后端 `/stats` 返回值一致 |
| 9 | 导出 | 触发成功，轮询到完成，产物行数与列表一致 |
| 10 | 权限 | 无 `trade:order:list` 访问 → 403；无 `trade:order:pii` 时「查看」按钮隐藏 |
| 11 | 构建 | lint / typecheck / unit / build 全绿 |

- 批量导出多个店铺
- 图表可视化（先做数字卡片）
